# EduAssist AI — LLMOps Prompt Engineering & Evaluation Assignment

An academic question-answering assistant LLMOps exercise: three prompt versions are tested,
their operational performance (latency, tokens, cost, JSON validity) is measured, and the best
version is promoted to production using the **MLflow Prompt Registry**.

## Model & access-method note

All LLM calls in this submission run **locally** against `Qwen/Qwen2.5-3B-Instruct` (ungated,
Apache-2.0, ~3B parameters) via Hugging Face `transformers`. Token counts come from that
model's own tokenizer. Cost is estimated from the **published** hosting rate for
`Qwen/Qwen2.5-7B-Instruct` (the smallest Qwen2.5 checkpoint currently listed by hosted
providers, via OpenRouter's aggregated pricing API, accessed 2026-11-04, USD) — see
`src/eduassist/config.py`. If you export a real `HF_TOKEN`, the code automatically switches to
calling the real Hugging Face Inference API instead (see `src/eduassist/llm_client.py`).

## Requirements

- **Python 3.12** (tested with 3.12.11; project also works on 3.10+ but 3.9 is EOL and not
  recommended — `transformers`/`torch` releases are dropping support for it).
- macOS/Linux/Windows with at least ~8GB free RAM and ~7GB free disk (for the model download).
  An Apple Silicon Mac (MPS) or CUDA GPU is recommended for reasonable latency; CPU-only works
  but is slower.
- Libraries: see `requirements.txt` (torch, transformers, accelerate, mlflow, pandas, etc.)

## Environment variables

| Variable   | Required? | Purpose                                                                 |
|------------|-----------|--------------------------------------------------------------------------|
| `HF_TOKEN` | Optional  | If set, switches Task 1-3 to call the real Hugging Face Inference API instead of running the model locally. |

Never hard-code tokens. Copy `.env.example` to `.env` (and `source` it, or use `python-dotenv`)
or `export HF_TOKEN=...` directly in your shell.

## Reproducing the experiment

1. Activate the environment (`source .venv/bin/activate`).
2. Open `notebooks/eduassist_llmops_assignment.ipynb` in VS Code / Jupyter and select the
   `.venv` kernel.
3. Run all cells top to bottom (Task 1 → Task 2 → Task 3). The first LLM call in the session
   downloads and loads `Qwen/Qwen2.5-3B-Instruct` (~6GB, one-time); subsequent calls reuse the
   loaded model. Total notebook runtime is roughly 10 minutes on an Apple Silicon Mac (MPS).
4. Outputs are written to:
   - `data/latency_tokens_cost.csv` (Task 1 + 2, 5 rows)
   - `data/prompt_evaluation_results.csv` (Task 3, 15 rows)
   - `mlruns/` (local MLflow tracking store — experiment `eduassist_llmops_assignment`, 3 runs,
     and the registered prompt `eduassist_answer_prompt` with 3 versions + a `production` alias)

### Viewing the MLflow UI

```bash
cd "MLOPS Assignment-2"
mlflow ui --backend-store-uri file:./mlruns --port 5001
```

Then open <http://127.0.0.1:5001>. Use the **Experiments** tab for the three logged runs and
their metrics, and the **Prompts** tab for the registered prompt, its three versions, the
version diff/compare view, and the `production` alias. (Port 5000 is the MLflow default but is
occupied by macOS AirPlay Receiver on many Macs — hence port 5001 above; use any free port.)

Screenshots of this evidence are saved under `screenshots/`.
